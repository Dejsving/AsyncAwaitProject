# Примеры к лекции по C#

Каждая тема находится в отдельном консольном проекте на .NET 8. Запускайте команды из корня репозитория:

| Тема | Проект |
|---|---|
| `async` / `await` и сгенерированная state machine | `AsyncAwaitProject` |
| `lock` (Monitor) и `SemaphoreSlim` | `02-MonitorAndSemaphoreSlim` |
| `async void` и исключение | `03-AsyncVoid` |
| Блокирующий `.Result` и неблокирующий `await` | `04-BlockingWait` |
| Пропуск `await` и намеренная параллельность | `05-AwaitOrNot` |
| Делегат как «ярлык» на метод, `Invoke` / `?.Invoke` | `06-Delegates` |
| Делегаты и события: подписка / отписка | `07-DelegatesAndEvents` |

Например:

```powershell
dotnet run --project .\AsyncAwaitProject\AsyncAwaitProject.csproj
dotnet run --project .\02-MonitorAndSemaphoreSlim\MonitorAndSemaphoreSlim.csproj
```

Для сборки всех примеров: `dotnet build .\AsyncAwaitProject.sln`.

## На что обратить внимание

- В первом примере рефлексия показывает тип, поля и интерфейс `IAsyncStateMachine`, которые компилятор сгенерировал для `GetNumberAsync`. Для изучения реализации метода откройте собранную DLL в декомпиляторе .NET, например ILSpy. `async` не создает отдельный поток сам по себе.
- Пример `lock` вынесен в `02-MonitorAndSemaphoreSlim/MonitorExample.cs`. Метод с `await` внутри `lock` оставлен в комментарии: раскомментируйте его, чтобы увидеть ошибку компиляции. `SemaphoreSlim.WaitAsync` позволяет ожидать вход асинхронно; освобождение должно быть в `finally`.
- Пример `async void` намеренно завершается необработанным исключением. `catch` вокруг вызова его не поймает; консольный процесс получает необработанное исключение и завершается. Запускайте этот проект отдельно. Ошибка не «исчезает» — для обычного кода используйте `Task` / `Task<T>`.
- В примере `.Result` поток, вызвавший свойство, заблокирован на время ожидания. Heartbeat таймера печатается с другого потока и наглядно показывает, что блокируется именно ожидающий поток, а не весь процесс.
- При пропуске `await` задача начинает выполняться, но вызывающий код идет дальше и не наблюдает ее результат. Компилятор намеренно выдает предупреждение CS4014; положительные примеры используют `await` и `Task.WhenAll`.
- В примере с делегатами тип `MathFunction` и явные методы `Sine` / `Square` показывают, что делегат — «ярлык» (алиас) на метод. В конце показан вызов через `Invoke` и `?.Invoke`, который безопасно пропускает вызов, если делегат равен `null`; тот же приём используется для событий в следующем примере.
- В последнем примере показаны два собственных типа делегата. Для каждого события компилятор предоставляет операции `+=` и `-=`, но вызывать событие может только сам объявивший его тип.
